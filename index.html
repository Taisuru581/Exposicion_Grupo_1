01 / RWD

¿Qué es el diseño responsivo?

Básicamente, consiste en hacer que una misma página acomode su contenido al espacio disponible. Por ejemplo, las tarjetas pueden aparecer una debajo de otra en el celular y en tres columnas en una computadora.

Ver un ejemplo
.destinos {  display: grid;  grid-template-columns: repeat(12, minmax(0, 1fr));}.destino { grid-column: span 12; }

Esta es la base para móvil: cada tarjeta ocupa las 12 columnas. Más adelante, las media queries cambian cuánto ocupa. En el ejemplo podemos verlo funcionando, no solamente en una imagen.

Para ampliar: W3Schools · Diseño responsivo ↗
02 / Mobile-first

Empezar por la pantalla pequeña

La idea es resolver primero el contenido en un espacio pequeño y agregar distribuciones más amplias cuando haya suficiente espacio. Así mantenemos visibles el texto, las imágenes y los controles que necesitamos.

Ver un ejemplo
.portada { grid-template-columns: 1fr; }@media (min-width: 768px) {  .portada { grid-template-columns: 1fr 1fr; }}

La regla inicial crea una columna. Desde 768 px se agregan dos. En lugar de identificar el modelo del celular, trabajamos con el ancho que tiene la página.

Para ampliar: W3Schools · HTML responsivo ↗W3Schools · Media queries ↗
03 / Maquetación

Usar medidas que puedan adaptarse

Un contenedor fluido, espacio entre los elementos y un límite de ancho ayudan a que el contenido se mantenga ordenado. Flexbox y CSS Grid nos permiten distribuirlo sin colocar cada elemento a mano.

Ver un ejemplo
* { box-sizing: border-box; }.contenedor {  width: min(1120px, 92%);  margin-inline: auto;}.navegacion { display: flex; flex-wrap: wrap; }

El 92% deja espacio a los lados; 1120 px limita el ancho en pantallas grandes. border-box incluye padding y borde dentro del tamaño. flex-wrap permite que los enlaces pasen a otra línea.

Para ampliar: W3Schools · CSS Grid ↗W3Schools · Flexbox ↗
04 / Viewport

Decirle al navegador cómo interpretar la pantalla

El viewport es el área donde el navegador muestra la página. En un celular necesitamos que su ancho corresponda al dispositivo, para que las reglas responsivas se apliquen como esperamos.

Ver un ejemplo
<meta name="viewport"      content="width=device-width, initial-scale=1">

width=device-width ajusta el viewport al ancho del dispositivo. initial-scale=1 establece la escala inicial. Lo colocamos dentro de head y dejamos que la persona pueda utilizar el zoom.

Para ampliar: W3Schools · Viewport ↗
05 / Media queries

Cambiar el diseño cuando hace falta

Una media query aplica CSS cuando se cumple una condición. El breakpoint es el punto donde decidimos hacer ese cambio. En esta demo usamos 768 y 1024 px para pasar de una a dos y luego a tres tarjetas por fila.

Ver un ejemplo
@media (min-width: 768px) {  .destino { grid-column: span 6; }}@media (min-width: 1024px) {  .destino { grid-column: span 4; }}

Las dos condiciones pueden cumplirse al mismo tiempo. En pantallas de 1024 px o más, la regla posterior de span 4 reemplaza span 6. Los breakpoints se eligen según lo que necesita el contenido.

Para ampliar: W3Schools · Media queries y breakpoints ↗
06 / Grid de 12

Dividir el ancho en partes

Podemos imaginar una fila dividida en 12 partes: 6 + 6 permite dos bloques iguales; 4 + 4 + 4 permite tres; 8 + 4 crea una distribución asimétrica. No hay que confundir el sistema de 12 columnas con la herramienta CSS Grid: son conceptos distintos.

Ver un ejemplo
.destinos {  display: grid;  grid-template-columns: repeat(12, minmax(0, 1fr));  gap: 1.5rem;}.destino { grid-column: span 4; }

En el ejemplo CSS construimos ese sistema con CSS Grid. Bootstrap implementa su grid tradicional con Flexbox. En ambos casos, la distribución se puede expresar como partes de una fila.

Para ampliar: W3Schools · Grid responsivo ↗
07 / Tipografía

Que el texto también se adapte

Si el título mantiene un tamaño enorme en el celular, ocupa demasiado espacio. Con clamp() definimos un mínimo, un tamaño que crece con la pantalla y un máximo. rem toma como referencia el tamaño de letra del elemento raíz.

Ver un ejemplo
h1 {  font-size: clamp(2.4rem, 1.2rem + 5vw, 5rem);  line-height: 1.04;}p { max-width: 65ch; }

El título cambia de manera gradual, incluso entre los breakpoints. El máximo en ch ayuda a que un párrafo no forme líneas demasiado largas.

Para ampliar: W3Schools · clamp() ↗
08 / Imágenes

Adaptar el tamaño y elegir el archivo adecuado

Con max-width: 100% evitamos que una imagen salga de su contenedor. srcset ofrece archivos de diferentes resoluciones y sizes describe el espacio que van a ocupar. picture permite elegir otra composición según una condición.

Ver un ejemplo
<picture>  <source media="(max-width: 767px)"          srcset="assets/img/bosque-800.jpg">  <img src="assets/img/playa-1400.jpg"       srcset="assets/img/playa-400.jpg 400w,               assets/img/playa-800.jpg 800w,               assets/img/playa-1400.jpg 1400w"       sizes="(min-width: 768px) 44vw, 92vw"       alt="Olas del mar vistas desde una costa"></picture>

En móvil, picture prioriza el bosque; en una pantalla más ancha, aparece la costa. Con srcset el navegador elige el archivo considerando el espacio y la densidad de píxeles. Bootstrap aporta img-fluid para adaptar la imagen al contenedor.

Para ampliar: W3Schools · Imágenes responsivas ↗W3Schools · picture ↗W3Schools · srcset en source ↗W3Schools · img-fluid ↗
2.1 / INTRODUCCIÓN

¿Qué nos aporta
Bootstrap?

Bootstrap es un framework de interfaz que reúne estilos, utilidades y componentes. Nos permite reutilizar una base para organizar y construir la página.

¿Por qué utilizarlo?

Podemos crear columnas, aplicar espaciados y agregar componentes usando clases que ya están definidas. Esto ayuda a mantener una apariencia consistente y a avanzar más rápido.

  • Una landing page con navegación, imágenes y formulario.
  • Un catálogo con tarjetas y enlaces entre páginas.
  • Un panel de administración con controles y pestañas.
Para ampliar: W3Schools · Introducción a Bootstrap 5 ↗

Mobile-first sigue siendo la base

En esta demo, col-12 ocupa toda la fila desde el inicio. col-md-6 permite dos bloques desde 768 px y col-lg-4 permite tres desde 992 px. Si aumenta el ancho, la regla sigue aplicándose hasta que otra la reemplaza.

El framework aporta herramientas, pero todavía debemos decidir el orden, el contenido y la facilidad de uso de nuestra página.

2.2 / VERSIONES

Bootstrap fue cambiando
con las necesidades de la web.

Para esta exposición usamos Bootstrap 5.3.8, que es la versión incluida en los archivos del grupo. La idea es mantener la misma versión en los archivos, las clases y los ejemplos.

Bootstrap 12011 · El punto de partida

Nació en Twitter para compartir una misma base visual: botones, formularios, navegación y estilos comunes.

Cómo empezó: La primera generación reunía esas herramientas en un solo proyecto. Su grid inicial tenía 16 columnas y estaba pensado principalmente para escritorio.

Documentación histórica de Bootstrap 1 ↗
Bootstrap 22012 · Llegan las opciones responsivas

Pasó a un grid de 12 columnas y agregó opciones para adaptar la página a diferentes anchos.

Qué cambió: Frente a la versión 1, ofrecía distribuciones fluidas y soporte responsivo que se incorporaba con una hoja de estilos adicional.

Documentación histórica de Bootstrap 2 ↗
Bootstrap 32013 · Mobile-first como base

El diseño empezó por las pantallas pequeñas y luego se ampliaba. También cambió a una apariencia más plana.

Qué cambió: Lo responsivo dejó de ser un archivo opcional: pasó al núcleo del framework. El grid usó clases por tamaño, como col-sm-6 y col-md-4.

Anuncio oficial de Bootstrap 3 ↗
Bootstrap 42018 · Flexbox y nuevas herramientas

El grid pasó a usar Flexbox. Sass reemplazó a Less y las tarjetas reunieron funciones de componentes anteriores.

Qué cambió: Frente a la versión 3, mejoró la alineación y el orden de los bloques, amplió las utilidades y utilizó rem en muchas medidas. JavaScript todavía dependía de jQuery.

Anuncio oficial de Bootstrap 4 ↗
Bootstrap · Cambios de 3 a 4 ↗
Bootstrap 52021 · JavaScript sin jQuery

Eliminó la dependencia de jQuery, incorporó soporte RTL y agregó herramientas como offcanvas y una API de utilidades.

Qué cambió: Frente a la versión 4, cambió atributos a data-bs-*, añadió el nivel xxl y usó start/end en clases de espaciado. Más adelante, la rama 5.3 agregó modos de color.

W3Schools · Bootstrap 5 ↗
Bootstrap 5.3.825 de agosto de 2025 · Nuestra versión

Es un parche de la rama 5.3: mantiene la estructura de Bootstrap 5 y corrige detalles del CSS y del JavaScript.

Qué cambió: Frente a 5.3.7, revierte un cambio que causaba problemas de foco en dropdowns y ajusta el cálculo de contraste y algunos spinners. Todos los ejemplos de esta demo usan 5.3.8.

Anuncio oficial de Bootstrap 5.3.8 ↗

¿Cómo leemos 5.3.8? El 5 identifica la versión mayor, el 3 la versión menor y el 8 el parche. Un cambio de generación puede modificar la forma de trabajar; un parche se concentra en correcciones.

2.3 / IMPLEMENTACIÓN

Dos maneras de incorporarlo.

Por CDN

El navegador descarga los archivos desde una dirección externa. Es cómodo para comenzar, pero necesita acceso a esa dirección. En el enlace dejamos fijada la versión 5.3.8.

<!-- CSS del framework desde un CDN --><link rel="stylesheet"      href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/css/bootstrap.min.css"><!-- El bundle incluye los componentes y Popper --><script src="https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/js/bootstrap.bundle.min.js"></script>
Para ampliar: W3Schools · CDN y primeros pasos ↗Bootstrap · Inclusión oficial ↗

De forma local · usada en esta demo

Guardamos el CSS y el bundle dentro de assets/vendor. Así podemos mostrar el ejemplo sin depender de una descarga externa durante la exposición. El bundle incluye Popper para los dropdowns.

<!-- CSS del framework guardado en el proyecto --><link rel="stylesheet" href="assets/vendor/bootstrap.min.css"><link rel="stylesheet" href="assets/css/ejemplo-bootstrap.css"><!-- Cargar primero el bundle clásico de Bootstrap 5.3.8 --><script src="assets/vendor/bootstrap.bundle.min.js"></script>

2.7 / FORMULARIOS

Pedir información
sin complicarle el proceso a la persona.

El formulario utiliza controles reales y muestra errores específicos. Al corregir un dato, el resto de la información permanece en su lugar.

Controls: elegir el elemento adecuado

input recoge nombre, correo y fecha. select permite elegir el ambiente. range permite escoger una cantidad entre 1 y 8. Los radio seleccionan el horario, el textarea recibe comentarios y el checkbox confirma que se trata de una simulación.

En Bootstrap 5 usamos form-control, form-select, form-range y form-check-input. Las etiquetas tienen form-label o form-check-label.

Para ampliar: W3Schools · Formularios ↗W3Schools · Select ↗W3Schools · Checks y radios ↗W3Schools · Range ↗

Validación básica y UX

  • Etiquetas visibles, campos obligatorios indicados y ejemplos.
  • Nombre de al menos dos caracteres y correo con formato básico.
  • Selección del ambiente y una fecha. No se comprueba si la fecha es futura.
  • Ayudas visibles asociadas con aria-describedby y avisos del navegador.
  • El primer campo incorrecto recibe el foco.
  • Página de ejemplo al completar los campos; no se realiza una reserva.

Usamos required, minlength y type="email". El navegador revisa estos atributos. Bootstrap da estilo a los controles y las ayudas quedan visibles con form-text.

Para ampliar: W3Schools · Validación ↗Bootstrap · Validación y estados ↗
